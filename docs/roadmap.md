# 【Name_ZH】 【Name_EN】 · 发展规划

> **把每一天写成自己的史书。**
>
> Plan your days. Keep your history.

> 当前仓库仍使用工作名「拾光 TODO」。本文使用产品名 **【Name_ZH】 / 【Name_EN】** 描述长期方向。

## 一句话价值

**【Name_ZH】把「今天要做什么」和「这一生做过什么」放进同一个地方：每天是一页，多年后自动装订成一部只属于你的史书。**

## 产品命名

| | |
|---|---|
| 中文名 | **xxx** |
| 英文名 | **xxx** |
| 中文一句话 | 把每一天写成自己的史书。 |
| English tagline | Plan your days. Keep your history. |
| 为什么叫这个名字 | 一天一页、一天一个 Markdown 文件；「【Name_ZH】」既是日程，也是记录，时间久了自然成为一部个人编年史。 |

备选方向：

- **历书 / Almanac**：更强调日历与年鉴感；
- **年谱 / Annals**：更强调「一生之书」，但偏回顾；
- **Sundial**：延续「拾光」的光与时钟意象，适合作为桌面时钟产品的名字。

## 现在在哪里

当前版本是一个**本地优先的 Markdown 日程工具**：

- 月 / 周 / 日三视图；
- 时段速记、拖动排序、任务详情、附件工作区；
- 置顶时钟、提醒、搜索；
- 数据目录 + `server.py`，用 Git / GitHub 手动完成多设备同步与备份。

它已经解决了「记录」和「本地数据所有权」，但还没有解决：

- 真正的多设备自动同步；
- 任务与文件的自动关联；
- AI 规划与回顾；
- 桌面常驻与专注计时；
- 移动端与小程序。

## 设计原则

后续所有阶段都遵守这几条：

1. **本地优先**：离线也能完整使用；云端是增强，不是前提。
2. **数据可带走**：Markdown / 通用文件格式，随时导出，不做锁定。
3. **隐私默认**：AI 和云同步都是显式开启；支持本地模型或自带 Key。
4. **渐进演进**：不一次性重写；先让现有用户无痛升级。
5. **安静的工具**：不做信息流、不做社交、不塞广告。

## 阶段规划

### Phase 1 · 打磨本地体验（v1.x）

目标：把现在这套「本地 Markdown + 三视图 + 附件 + 时钟」打磨到可以长期日常使用。

- 自动化测试：Markdown 解析、附件事务、跨月移动、冲突处理；
- 性能：大量日文件下的搜索、月视图加载、附件缩略图；
- 可访问性：键盘操作、焦点管理、对比度；
- 安装体验：一键启动脚本、Windows 快捷方式、端口自动选择；
- 文档：使用手册、故障排查、数据恢复；
- 数据安全：可选的本地快照 / 导出（不做云端自动备份）。

**交付标准**：连续使用一周不需要打开编辑器修数据。

### Phase 2 · 任务即工作区（v2.0）

目标：把「任务」变成真正的工作单元，文件和任务自动绑定，不再手动建文件夹。

核心变化：

- 新建任务时自动创建稳定的任务工作区：`workspaces/<taskId>/`；
- 拖入任务的文件自动进入工作区，并被索引、预览、搜索；
- 任务详情里直接看到该任务的所有文件、版本和时间线；
- 文件可以来自拖拽、粘贴、系统「发送到」、桌面端文件夹监听；
- 工作区跨月份稳定存在，不再随月份目录搬家。

技术要点：

- 从 `YYYY-MM/attachments/<taskId>-<title>/` 迁移到按任务 ID 的稳定目录；
- Markdown 里的附件引用保持可读，增加映射索引；
- 内容哈希去重、版本记录、回收站；
- 大文件分块上传与断点续传。

**交付标准**：新建一个任务，把资料拖进去，关掉页面再打开，文件和任务仍然在一起。

### Phase 3 · 云空间与多设备（v2.5）

目标：从「借 GitHub 同步」升级为产品自己的云空间。

- 账号体系：邮箱 / 第三方登录；
- 多设备同步：Web、桌面端、移动端、小程序共享同一份数据；
- 离线优先：本地缓存 + 操作队列，联网后自动合并；
- 冲突处理：按任务 ID 和字段合并，保留版本历史，冲突可回看；
- 附件对象存储：分块上传、断点续传、CDN 加速；
- 端到端加密（可选）：用户持有密钥，服务端看不到明文；
- 版本历史与回收站：误删可恢复；
- GitHub 仍可作为导出 / 备份目标，而不再是同步层。

技术要点：

- Markdown 仍是可读的导出格式；云端可以用结构化索引加速查询；
- 同步协议需要版本向量 / 操作日志，避免「最后写入者获胜」丢数据；
- 存储分层：元数据数据库 + 对象存储 + 搜索索引；
- 配额、限流、成本监控。

**交付标准**：两台设备改同一天的任务，联网后都看到一致结果，且能查看历史版本。

### Phase 4 · 桌面端与专注（v3.0）

目标：让【Name_ZH】成为桌面上常驻的一小块安静空间。

- 桌面应用：优先 Tauri（体积小、原生），Electron 作为备选；
- **磨砂玻璃悬浮窗**：Windows Acrylic / Mica，macOS Vibrancy；
- 悬浮窗显示今天的 ToDo、当前时段、下一项；
- 可最小化到托盘 / 收起为纯时钟；
- 全局快捷键：快速新建、开始专注、打开今天；
- **番茄钟**：25/45/90 分钟可配置，任务级开始 / 暂停 / 结束；
- **时间统计**：每个任务的实际投入、专注时长、打断次数；
- 空闲检测与手动修正；
- 原生通知、开机自启、多显示器支持。

技术要点：

- 桌面端复用 Web 前端，通过 Tauri 提供窗口、托盘、通知、文件监听；
- 时间统计先本地记录，再同步到云端；
- 悬浮窗性能：常驻低占用，避免每秒重绘整个界面。

**交付标准**：开机后悬浮窗常驻，点一下任务就能开始番茄钟，晚上能看到今天每个任务花了多久。

### Phase 5 · AI 规划与人生史书（v3.5）

目标：让积累的数据反过来帮助规划，并自动编成「自己的史书」。

#### AI 规划

- 根据 backlog、优先级、截止日期、日历和精力时段，生成日计划 / 周计划；
- 周复盘：本周完成了什么、卡在哪里、下周建议；
- 月度 / 年度规划：目标拆解、节奏建议、缓冲时间；
- 所有建议先以草稿呈现，用户确认后才写入任务；
- 可解释：每条建议引用对应的任务、备注或文件。

#### AI 总结与史书

- 自动生成日 / 周 / 月 / 年总结；
- 提取成果、阻碍、主题、关键词、里程碑；
- 把任务、笔记、文件、时间统计串成时间线；
- 生成「年鉴」：每年一卷，可编辑、可导出 PDF / Markdown；
- 语义搜索：用自然语言找过去的任务和资料；
- 引用与溯源：总结里的每条结论都能点回原始记录。

#### 隐私与模型

- 默认关闭，按工作区 / 按功能开启；
- 支持云端 API、自带 API Key、本地模型三种模式；
- 发送前脱敏；附件内容按需读取；
- 明确告知哪些数据会被发送；
- 成本控制：摘要缓存、批量生成、token 预算。

**交付标准**：连续使用三个月后，能一键生成一份自己愿意保存和回看的月度总结。

### Phase 6 · 小程序与生态（v4.0）

目标：在手机上用最轻的方式查看和记录，并与桌面端数据互通。

- 微信小程序 / 移动端 Web：
  - 今天视图、快速添加、完成勾选；
  - 番茄钟 / 计时（受小程序后台限制）；
  - 查看 AI 周报 / 月报；
  - 微信登录，扫码与桌面端绑定；
- 日历集成：ICS 订阅、Google / Outlook / Apple 日历；
- 分享：把某个任务工作区或某篇总结生成只读链接；
- 模板市场：周计划、科研、创业、考试等模板；
- 开放 API / Webhook：让其它工具写入任务、触发总结。

小程序限制：

- 没有任意文件系统，附件通过云端 API 上传；
- 后台计时受限，长时间计时需要服务端校正；
- 审核与合规成本；
- 首版建议只做「今天 + 快速记录 + 查看总结」，不做完整编辑器。

**交付标准**：手机上 10 秒内记下一个想法，回到电脑能看到它，并且能进入当天的计划。

## 推荐顺序

```text
Phase 1  打磨本地
   │
Phase 2  任务即工作区
   │
Phase 3  云空间 / 多设备
   │
   ├──────────────┐
Phase 4 桌面端      Phase 5 AI
   │              │
   └──────┬───────┘
      Phase 6 小程序 / 生态
```

- 先做工作区，再做云同步：数据模型稳定后再同步，返工最少。
- 桌面端和 AI 可以并行：桌面端解决「每天愿不愿意打开」，AI 解决「数据有没有价值」。
- 小程序最后做：它依赖云、账号和稳定的数据模型。

## 架构演进

### 现在

```text
浏览器 SPA ── /api/* ── server.py ── data/*.md
```

### 云阶段

```text
Web / Desktop / Mobile
        │
   Sync Client（本地缓存 + 操作队列）
        │
   Sync Service（鉴权、合并、版本）
        │
   Metadata DB + Object Storage + Search Index
        │
   AI Service（规划 / 总结 / 语义搜索，可选）
```

### 关键决策

| 决策 | 倾向 | 原因 |
|---|---|---|
| Markdown 是否仍是主格式 | 是 | 可读、可导出、可被其它工具使用 |
| 云端是否用数据库 | 是，作为索引 | 查询、同步、AI 需要结构化数据 |
| 同步冲突策略 | 任务级 + 字段级合并 | 比整文件覆盖更安全 |
| 桌面技术 | Tauri 优先 | 体积小、内存低、原生窗口能力 |
| AI 默认 | 关闭，显式开启 | 隐私与成本 |
| 小程序范围 | 轻量记录 + 查看 | 平台限制与审核成本 |

## 风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| 同步复杂度 | 离线编辑、冲突、重复附件 | 先做工作区模型，再做同步；保留版本历史 |
| 云成本 | 附件存储、AI token | 配额、分层存储、摘要缓存、付费层 |
| AI 隐私 | 任务和文件可能敏感 | 默认关闭、脱敏、本地模型、自带 Key |
| AI 幻觉 | 总结可能编造 | 引用溯源、用户确认、可编辑 |
| 小程序限制 | 无文件系统、后台受限 | 首版只做轻量功能 |
| 桌面打包 | 签名、更新、跨平台 | Windows 先行，自动更新后置 |
| 范围膨胀 | 一次想做太多 | 每个阶段有明确交付标准，不达标不进入下一阶段 |

## 明确不做

- 不做信息流、社交动态、排行榜；
- 不做广告；
- 不做强制云同步；本地永远可用；
- 不做数据锁定；始终支持完整导出；
- 首版不做多人实时协作编辑（共享 / 只读链接可以后置）。

## 成功指标

- **留存**：D7 / D30 留存；连续使用天数；
- **使用深度**：每人每天创建 / 完成任务数；附件使用率；
- **同步质量**：同步成功率、冲突率、恢复成功率；
- **AI 价值**：周报 / 月报的打开率、保存率、编辑率；
- **桌面端**：悬浮窗常驻时长、番茄钟使用次数；
- **信任**：导出成功率、用户主动备份比例。

## 开放问题

- 云端部署在哪个平台？成本与合规如何平衡？
- 端到端加密与 AI 总结如何共存？（本地解密后计算，还是用户授权云端明文？）
- Markdown 与结构化数据库的双写如何保证一致？
- 任务工作区的文件是复制进云端，还是支持「链接本地文件夹」？
- 桌面端先支持 Windows，还是 Windows + macOS 同步推进？
- 免费版与付费版的边界在哪里？
- 是否开放核心协议 / SDK，让第三方客户端接入？
