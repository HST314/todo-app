# 附件管理

附件按任务隔离，每个任务在当月有独立文件夹。文件会被复制进数据目录，而不是只记录原路径，因此移动原文件不会导致附件失效。

## 目录结构

```text
data/2026-10/
├── 2026-10-29.md
└── attachments/
    └── t-a1b2-写论文初稿/
        ├── 实验截图.png
        └── 需求文档.pdf
```

- 文件夹名 = `任务ID-标题`，标题会做安全化处理（空格和特殊字符变成 `-`，最多 32 字）。
- **按需创建**：第一次真正上传附件时才创建文件夹；没有附件就没有空目录。
- 同一个任务的所有附件都在同一个文件夹里。

## 添加附件

在任务详情面板的「附件」区域：

1. 把文件拖进虚线框，或点击虚线框选择文件（支持多选）；
2. 文件立即出现在列表里，带「待保存」标记；
3. 图片会用本地文件直接预览；
4. 点击「保存」后才真正上传。

### 待保存状态

- 此时磁盘上**还没有**文件，任务文件夹也可能还不存在；
- 「打开文件夹」会锁定，点击提示「请先保存文件」；
- 点击待保存的附件行也会提示先保存；
- 移除待保存的附件不会产生任何磁盘文件。

### 上传过程

点保存后：

- 保存按钮显示转圈和 `正在上传附件 2/3…`；
- 详情面板暂时不可编辑，关闭会被拦截；
- 全部附件上传成功后才写 Markdown，然后关闭面板。

### 上传失败

任意一个附件上传失败时：

- 中止本次保存；
- 删除本次已经上传成功的文件；
- 保留「待保存」列表，Markdown 不变；
- 详情面板保持打开，可以直接重试或移除失败项。

### 链接附件

在链接输入框粘贴 `https://…`，点「加链接」。链接不涉及文件复制，保存时直接写入 Markdown。

## 打开与定位

| 操作 | 行为 |
|---|---|
| 详情里的「打开文件夹」 | 在系统文件管理器中打开该任务的附件文件夹 |
| 点击已保存的附件行 | 打开资源管理器并选中该文件 |
| 点击链接附件 | 浏览器新标签页打开 |
| 存在待保存附件时 | 「打开文件夹」锁定，点击提示先保存 |

「打开文件夹 / 定位文件」依赖本地服务 `server.py`，普通静态服务器无法唤起资源管理器。

## 改名与移动

- **改标题**：保存后附件文件夹自动改名为新的 `任务ID-标题`，Markdown 里的路径同步更新；改名失败会中止保存，不会留下断链。
- **改日期（同月）**：文件夹不动。
- **改日期（跨月）或跨月拖动**：整个附件文件夹复制到目标月份，Markdown 保存成功后再删除旧文件夹；失败会回滚。
- **撤销跨月拖动**：文件夹会搬回原月份。

## 移除与删除

### 移除单个附件

点击附件行右侧「移除」，然后保存：

1. 如果这是本次新加、还没上传的文件：直接从列表移除，不产生磁盘文件；
2. 如果这是已经保存的文件：保存时会二次确认，确认后**真实删除磁盘文件**；
3. 任务文件夹变空时，会自动删除空文件夹。

### 删除任务

删除带附件的任务时：

- 会连同整个任务附件文件夹一起删除；
- **不可撤销**；
- 删除前会弹确认。

> 删除是真实删除，Git 是唯一的恢复手段。请把数据目录纳入版本管理，或自行备份。

## 文件名规则

- 非法字符 `< > : " / \ | ? * ( )` 和空白会替换为 `_`；
- 首尾的下划线和点会被清理；
- 文件名最长约 90 个字符，保留扩展名；
- 同名文件自动加 `-2`、`-3`；
- 单个附件上限 2 GB（服务端限制）。

## 旧版附件

旧版 `assets/` 目录下的附件**不兼容**：

- 不会自动迁移；
- 不支持定位、删除；
- 不会自动清理；
- 确认不再需要后可以手动删除。
