# 数据与备份

拾光不使用数据库。一天一个 Markdown 文件，任务、备注、附件引用都在里面。

## 数据目录

首次打开时选择的数据文件夹就是数据根目录，可以放在任何位置：

```text
data/
├── 2026-10/
│   ├── 2026-10-29.md
│   ├── 2026-10-30.md
│   └── attachments/
│       └── t-a1b2-写论文初稿/
│           └── 实验截图.png
└── 2026-11/
    └── 2026-11-01.md
```

- 目录绝对路径保存在 `todo-app/config.json`；
- `config.json` 已加入 `.gitignore`，不会提交；
- 也可以在启动时直接指定：

```bash
python server.py --data "D:\path\to\your\data"
```

- 在「设置 → 数据文件夹 → 更换文件夹」里可以随时切换；
- 切换只改变读写目标，不会移动或删除旧数据。

## 一天一个文件

文件名固定为 `YYYY-MM-DD.md`，放在 `YYYY-MM/` 目录下。

```markdown
# 2026-10-29 周四

## 任务

- [ ] 写论文初稿 @09:00-11:00 !高 #科研 ^t-a1b2
  > 先改引言，再补实验
  - ![实验图](attachments/t-a1b2-写论文初稿/实验截图.png)
  - [需求文档](attachments/t-a1b2-写论文初稿/需求文档.pdf)
  - [参考链接](https://example.com)
- [ ] 整理实验数据 @上午 !中 #科研 ^t-c3d4
- [x] 健身 @19:00-20:00 !低 #生活 ^t-e5f6

## 备注
（手写内容，工具原样保留）
```

### 任务行语法

| 语法 | 含义 |
|---|---|
| `- [ ]` / `- [x]` | 未完成 / 已完成 |
| `@上午` `@下午` `@晚上` | 所属时段，唯一参与布局的定位信息 |
| `@09:00` / `@09:00-11:00` | 可选精确时间，仅作为卡片标签 |
| `!高` `!中` `!低` | 优先级，不写默认中 |
| `#科研` | 类别，不写默认其他 |
| `^t-a1b2` | 稳定 ID，手写时可省略 |
| 缩进 `> 文字` | 任务备注 |
| 缩进 `- [文字](地址)` | 附件或链接 |
| 缩进 `- ![文字](地址)` | 图片附件 |

### 规则

- 保存时按「上午 → 下午 → 晚上」重新分组，组内保持你拖出来的顺序。
- 精确时间的开始时间决定所属时段：
  - 06:00–11:59 → 上午
  - 12:00–17:59 → 下午
  - 18:00–05:59 → 晚上
- 旧语法 `@未安排` 会归入上午，保存时改写为 `@上午`。
- ID 由工具维护，任务改名、改日期、拖动时保持不变；只有 ID 冲突时才会重新生成。
- 任务区里的其他内容、`## 备注` 和其他 `##` 小节会原样保留。
- 手动编辑 Markdown 是允许的；保存时格式会被规范化，但内容不会丢。

## 冲突检测

每次读取文件都会记下修改时间（mtime）。保存时如果磁盘上的文件已经变了：

- 弹窗提供「重新加载 / 覆盖磁盘 / 取消」；
- 重新加载：丢弃页面里的修改，读取磁盘版本；
- 覆盖磁盘：用页面里的版本覆盖；
- 取消：不写入。

写入采用「临时文件 + 原子替换」，不会出现写了一半的文件。

## 用 Git 备份

推荐把数据目录放进一个 Git 仓库：

```bash
cd "D:\File\科研\TODO"
git add todo-app/data
git commit -m "更新任务"
```

建议：

- 只提交 `data/`，不要提交 `todo-app/config.json`（已 gitignore）；
- 附件是普通文件，会一起进入版本历史；
- 删除附件是真实删除，Git 是唯一恢复手段；
- 可以定期 `git tag` 或 `git push` 到私有远端。

## 迁移与换机

1. 复制整个数据目录；
2. 在新机器上启动 `python server.py`；
3. 在页面里重新选择该目录（`config.json` 保存的是本机绝对路径）。

如果只是移动了项目目录，启动后如果提示数据文件夹不存在，重新选择一次即可。

## 并发使用

- 建议只开一个页面/一个标签页编辑同一批任务；
- 外部编辑器修改文件是安全的，保存时会触发冲突提示；
- 不要同时运行多个会写入同一目录的工具。

## 限制

- 单个 Markdown 文件上限 32 MB；
- 单个附件上限 2 GB；
- 不支持二进制格式的 Markdown（必须是 UTF-8 文本）；
- 旧版 `assets/` 附件不兼容、不迁移、不自动清理。
